ScriptedLines — Roles and Access
Generated: 2026-07-24 (revised: ScriptedLines Admin became a real role)
=================================================================

One axis of permission: company-scoped `role` (every user has exactly
one) — owner, admin, draftsman, viewer, scriptedlines_admin.

(Earlier this session, ScriptedLines Admin was a separate
`is_platform_admin` boolean flag orthogonal to `role`. That was
reversed — it's now the 5th `role` value, single source of truth.)

Enforcement lives in: backend/auth.py (require_same_company,
require_not_viewer, require_platform_admin), and per-endpoint checks
in backend/api/{projects,drawings,companies,users,laminates,cores}.py.

-----------------------------------------------------------------
OWNER
-----------------------------------------------------------------
- Everything Draftsman can do (see below), plus:
- Edit company settings (name, address, contact info, logo)
- View and regenerate the company's join code
- Change any user's role within the company (promote/demote) —
  EXCEPT to/from scriptedlines_admin, see that section below
- Created automatically as the first user when a new company
  self-registers (POST /companies/register)

Note: in the current code, Owner and Admin are enforced IDENTICALLY —
every permission check that gates an owner-only-sounding action
actually checks `role in (owner, admin)`. There is no owner-only
action that admin can't also do. "Owner" is really just the label
given to whoever registered the company first.

-----------------------------------------------------------------
ADMIN
-----------------------------------------------------------------
- Same permissions as Owner (see note above) — company settings,
  join code, changing other users' roles — plus everything
  Draftsman can do.
- Never auto-assigned; a user only becomes Admin if an Owner/Admin
  changes their role via PUT /users/:id.

-----------------------------------------------------------------
DRAFTSMAN  (default role for everyone who self-registers)
-----------------------------------------------------------------
- Create, edit, and archive projects (own company only)
- Create, edit, delete, commit revisions, submit-to-client, and
  final-commit drawings (own company only)
- Add/remove laminates and cores to/from a project
- View/edit their own profile (name, initials) — NOT their own role
- Cannot edit company settings, view/regenerate the join code, or
  change any user's role (all gated to owner/admin)
- This is what everyone gets by joining via a company's join code —
  there's no self-service way to become owner/admin; an existing
  owner/admin has to promote you afterward.

-----------------------------------------------------------------
VIEWER
-----------------------------------------------------------------
- Can view: project list/detail, drawing list/detail, laminates/cores
  list (own company)
- CANNOT: create/edit/archive projects; create/edit/delete/commit/
  submit/finalize drawings; add/remove laminates or cores — all
  blocked with a clear 403 ("Viewer accounts don't have permission
  to ...")
- Cannot edit company settings or change roles (same as Draftsman)

-----------------------------------------------------------------
SCRIPTEDLINES_ADMIN  (platform-level tier, now a real role value)
-----------------------------------------------------------------
- Read-only visibility into EVERY company's projects and drawings —
  list and view, across all companies, not just their own
- Cannot create/edit/delete/archive/commit anything outside their own
  company — blocked with a clear 403 explaining the read-only
  boundary (not the vague 404 non-admins get for cross-company access)
- Within their own company (the internal "ScriptedLines" org), has no
  further meaningful permissions — that company has no real work in it
- Granted ONLY at registration time via a secret code
  (PLATFORM_ADMIN_SECRET env var). Explicitly BLOCKED from the generic
  PUT /users/:id role-change endpoint — an owner/admin of any company
  cannot grant this to one of their own users, even though it's a
  normal-looking role value. This guard is the whole reason it's safe
  for scriptedlines_admin to be a real role instead of a separate
  admin-only-settable flag: without it, any company owner could hand
  out cross-company read access to anyone.
- Purpose: customer support / debugging visibility (see something a
  customer is describing without needing DB access or a screen-share)
  without the blast radius of real write access to their data
- UI: the profile menu shows the "ScriptedLines Admin" badge instead
  of the raw role text — `role.value` is the snake_case string
  "scriptedlines_admin", which the existing capitalize CSS can't
  turn into something presentable, so it's special-cased to the badge

-----------------------------------------------------------------
ALL ROLES / UNIVERSAL
-----------------------------------------------------------------
- Unauthenticated requests → 401 (no token, or expired/invalid)
- A user of any role, trying to access another company's project or
  drawing by ID (and NOT scriptedlines_admin) → vague 404 "Not found",
  not 403 — deliberate anti-enumeration behavior so a foreign-tenant
  ID never confirms whether it exists
- Every user can view/edit their own profile's name/initials
  (PUT /users/:id, self always allowed) — but never their own role,
  and never to/from scriptedlines_admin regardless of caller's role
